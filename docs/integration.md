## 通信ポートを選ぶ

`SLT5006`は`Stream&`を受け取るので、`SoftwareSerial`、`Serial1`、その他の互換UARTクラスを使えます。

```cpp
SLT5006 sensor(Serial1);

void setup() {
  Serial1.begin(SLT5006::BAUD_RATE);  // 9600 bps, 8N1
}
```

実運用ではハードウェアUARTを優先してください。`SoftwareSerial`は簡単な動作確認には便利ですが、次の制約があります。

- 同時に受信待ちにできる`SoftwareSerial`は1つだけです。
- RXに使えるピンはボードによって異なります。
- 送受信中は割込みが制限されるため、Servo、タイマ処理、別のソフトウェアUARTなどの動作に影響することがあります。
- メインループの負荷が高いと、受信バイトを取りこぼすことがあります。負荷の高い状態で評価してください。

1つのUARTを複数のタスクや割込み処理から同時に操作しないでください。1つのUARTに接続できるSLT5006は1台だけです。

独自の`Stream`を使う場合は、`flush()`を現在のArduino仕様どおりに実装してください。未送信データの送信完了を待ってから戻るか、書込みが同期式なら何もせずに戻る実装にします。`flush()`では受信済みのデータを破棄しないでください。また、`available()`の確認直後に別の処理がそのバイトを読み取り、`read()`が`-1`を返した場合でも、タイムアウト処理が先へ進むように実装してください。

運用中にどちらか一方の電源だけが切れる場合も考慮してください。Arduinoが動作したままセンサの電源だけが切れたときにTXを駆動し続けると、信号線を通じてセンサへ逆給電されるおそれがあります。センサに電源が入っていない間は、UART出力をハイインピーダンスにするか、電源オフ時の逆給電防止（powered-off protection）機能を持つ変換器で信号を分離するか、製品資料に沿った同等の対策を入れてください。再起動、保守作業、コネクタの抜け、電源故障の場面も含めて確認してください。

## ブロッキングAPI

単純な周期測定には`readMeasurement()`を使います。この関数を1回呼ぶと、測定の開始から完了待ち、測定値の読出しまでを実行します。

```cpp
SLT5006::Measurement value;
if (sensor.readMeasurement(value)) {
  saveValue(value.vwcPercent);
} else {
  logError(sensor.lastError());
}
```

既定の設定では、開始ACKを受け取ってから300 ms待ち、その後は200 ms間隔で状態を確認します。開始ACKから30秒が経過すると、新しい状態確認は始めません。待っている間もアプリケーションの他の処理を進める必要がある場合は、協調ポーリングAPIを使います。

## 協調ポーリングAPI

状態遷移は次のとおりです。

```text
IDLE --startMeasurement()--> MEASURING
MEASURING --measurementComplete(false)--> MEASURING
MEASURING --measurementComplete(true)--> READY
READY --readMeasurementData()--> IDLE
```

`measurementComplete()`は、開始ACKから300 msが経つまでは、UARTで要求を送らずに`complete=false`を返します。その後も、前回の状態確認から設定したポーリング間隔が経っていなければ要求を送りません。そのため、メインループから繰り返し呼び出せます。完全な例は[`UnoCooperativePolling`](../examples/UnoCooperativePolling/UnoCooperativePolling.ino)を参照してください。

協調ポーリングAPIで分割できるのは測定変換の待ち時間だけで、UARTの応答待ちは分割できません。既定の30秒は測定完了を待つ時間の上限で、通常の測定にかかる時間ではありません。`startMeasurement()`、状態確認の要求を送るときの`measurementComplete()`、18バイトを読む`readMeasurementData()`は、それぞれ要求と応答を1回ずつやり取りします。応答を待つ間は呼出し元が止まり、その時間は最長で応答タイムアウト1回分（既定値で約300 ms）です。状態確認と測定値の読出しを続けて行う場合は、両方の待ち時間を見込んでください。これより厳しい応答性が必要な場合は、UART通信を独自の非同期状態機械、RTOSのタスク、または専用の通信処理に分けてください。

上記の順序を守らずに`readMeasurementData()`を呼ぶと、`MEASUREMENT_NOT_READY`になります。通信エラーが起きた場合は、その測定の状態を破棄し、間隔を空けてから`startMeasurement()`からやり直してください。

## タイムアウト

```cpp
sensor.setResponseTimeout(300);      // 1応答の受信待ち [ms]
sensor.setPollInterval(200);         // 状態確認の最小間隔 [ms]
sensor.setMeasurementTimeout(30000); // 測定変換待ち期限 [ms]
```

既定値は、このサンプルで基準として使っている値です。短くすると、正常な範囲の遅れもエラーと判定されることがあります。長くすると、断線の検出が遅れます。変更した場合は、実際のボード、UART、配線、センサ、温度範囲で評価してください。

タイムアウトの計算には符号なしの差分を使うので、`millis()`が最大値から0に戻っても正しく動作します。

`measurementTimeout`は、API呼出し全体にかかる実時間の上限ではありません。開始ACKから数えて、新しい状態確認を始められる変換待ちの期限です。期限の直前に始まったUARTの応答待ちや、ブロッキングAPIのポーリング間隔の待ちは期限で打ち切られないため、呼出しが期限を越えて続くことがあります。処理期限が厳しいシステムでは、各要求の`responseTimeout`も含めて余裕を持たせるか、上位で期限を管理してください。

## エラー処理と再試行

センサと通信するAPIは、成功すると`true`、失敗すると`false`を返します。

```cpp
if (!sensor.readMeasurement(value)) {
  Serial.println(sensor.errorMessage());
  if (sensor.lastError() == SLT5006::DEVICE_ERROR) {
    Serial.println(sensor.lastDeviceErrorCode(), HEX);
    Serial.println(sensor.deviceErrorMessage());
  }
}
```

推奨する対応:

1. エラーの種類、センサのエラーコード、時刻を記録する。
2. 同じ周期の中で要求を繰り返し送らず、次の測定周期まで待ってから再試行する。
3. 失敗が続く場合は、電源、GND、UARTの信号レベル、配線、ノイズを確認する。
4. 配線を変更する前に、必ず電源を切る。

センサが測定開始のACKを返した後に内部の測定に失敗すると、ACKとは別のエラーフレームが遅れて届くことがあります。次の要求を送る前に受信を再同期し、その後に返るデバイスエラー、応答形式のエラー、測定タイムアウトは、測定の失敗として扱ってください。このドライバは要求を送る前に毎回、受信バッファに残っているデータを破棄します。そのため、遅れて届いたエラーフレームや途中で途切れたフレームが残っていても、次の要求または次の周期から再同期できます。

## ファームウェアによる機能の違い

起動時にセンサ情報を読み、ココピート向けPore ECを使えるかどうかを保持しておきます。

```cpp
SLT5006::SensorInfo info;
bool hasCocoPoreEc = false;
if (sensor.readInfo(info)) {
  hasCocoPoreEc = SLT5006::supportsEcPoreCoco(info);
}
```

- ファームウェア1.6.3: `ecPoreCocoDsM`に非対応
- ファームウェア1.7.5、1.7.6: 対応

非対応のファームウェアでもword 9は読み出せますが、その値は0で、測定値としては使えません。ファームウェアが非対応の場合や、ファームウェアを識別できなかった場合は、この値を表示、保存、アップロードしないでください。その他の測定値は、それぞれの製品仕様に従って評価してください。

## メモリとデータの受け渡し

- ドライバは動的な`String`、ヒープ確保、例外を使いません。
- 受信フレームには、最大長に合わせた31バイトの固定長配列を使います。
- `Measurement`が公開するのは、アプリケーションで使う換算済みの`float`値だけです。
- 単位は、ECがdS/m、VWCが%、温度がdegC、電圧がVです。保存先の列名にも単位を含めることをおすすめします。
- Arduino Unoの`double`は`float`と同じ32ビットです。これより高い精度が必要な場合は、対象ボードとデータ形式も含めて、要件を別途評価してください。

## 測定値の選択と妥当性

通信の成否と測定値の妥当性は、分けて判定してください。

1. ファームウェアとシリアル番号を読み、CRCの正しい応答が返ることで通信経路を確認する。
2. 使用する培地に合わせて、VWCのフィールドを1つ選ぶ（一般土壌は`vwcPercent`、ロックウールは`vwcRockPercent`、ココピートは`vwcCocoPercent`）。
3. 必要な物理量に応じて、Bulk ECとPore-water ECを区別する。
4. `ecPoreCocoDsM`を使う場合は、ファームウェアの対応に加えて、製品資料に記載された適用条件も確認する。
5. 公式の[推奨設置方法](https://www.murata.com/ja-jp/products/sensor/soil/design-development/institution)に従って設置し、性質のわかっている培地と設置条件で、値の変化と再現性を確認する。
6. 仕様範囲外の値、飽和、異常値の扱いをシステム要件として決める。ドライバは受信した値を仕様範囲内に収める処理をしない。

培地ごとの換算値を、同時に得た独立の測定値として保存したり平均したりしないでください。

## 移植・独自実装時の確認事項

独自のドライバに移植する場合は、[プロトコル資料](protocol.md)に加えて、特に次の項目をテストしてください。

- CRCの計算値と、CRCを上位バイトから送る順序
- 分割して届く応答の組み立て
- 4バイトのエラー応答と通常応答の長さの判定
- CRC、機能コード、アドレス、サイズ、書込みエコーが一致しない応答の拒否
- 符号付き12ビットの温度値とリトルエンディアンの値の解釈
- 測定開始から300 msが経つまで状態要求を送らないこと
- 30秒の測定タイムアウトと、`millis()`が最大値から0に戻るときの動作
