# M5Core2CloudLogger設定ガイド

[English](logger-setup.md) | 日本語

`M5Core2CloudLogger`は、SLT5006の測定と画面表示に加えて、microSDへのCSV保存、Wi-Fi/NTP、GoogleスプレッドシートへのHTTPS送信、送信に失敗したデータの再送キューを備えています。最初に[配線ガイド](m5stack-wiring.ja.md)を読み、`M5Core2QuickStart`でセンサ情報と測定値を確認してから、このロガーを使ってください。

## microSDを準備する

microSDには、測定結果のCSVと送信待ちのキューを保存します。対応するファイルシステムと容量は、使用するCore2とライブラリの資料で確認してください。カード上の必要なデータをバックアップしてから、Core2の電源を切った状態でmicroSDを装着します。

## 設定の読み込み優先順位

1. NVSに設定が保存されていれば、その設定を使います。
2. NVSが未設定の場合に限り、microSDのルートにある`/slt5006.cfg`を読み込みます。
3. どちらもない場合は、オフラインの既定値（60秒周期）で動作します。

NVSとSDの設定を項目ごとに組み合わせることはありません。NVSに保存した設定がオフライン設定であっても（USBから`{}`を送った場合を含む）、SDの設定は読みません。NVSの読み出しエラーや破損は、未設定とは扱いません。この場合は画面とUSBシリアルにエラーを表示し、オフラインの既定値で動作します。SDから読み込んだ設定は、NVSへ自動では保存しません。

## microSDから設定する

NVSが未設定の状態で使う場合は、microSDのルートにUTF-8で`/slt5006.cfg`を作成します。カードに設定ファイルを書き込む代わりに、USB経由でNVSへ設定を保存することもできます。PCからリムーバブルメディアへの書き込みが制限されている場合は、こちらの方法を使ってください。手順は次節で説明します。

```ini
wifi_ssid=YOUR_WIFI_SSID
wifi_password=YOUR_WIFI_PASSWORD
gas_url=https://script.google.com/macros/s/REPLACE_WITH_DEPLOYMENT_ID/exec
gas_token=REPLACE_WITH_RANDOM_TOKEN
sample_interval_sec=60
upload_batch_size=10
ntp_server=pool.ntp.org
timezone=JST-9
deep_sleep_sec=0
```

編集したらCore2を再起動します。ファイルサイズは最大4096バイトで、改行はLFとCRLFのどちらでも使えます。空行と、`#`または`;`で始まる行は無視します。キーと値の前後の空白は取り除きます。値全体を一重引用符または二重引用符で囲むと、値の内側の空白はそのまま残ります。同じキーが複数ある場合は、最後の値を使います。未知のキー、`=`のない行、不正な整数、範囲外の値、NUL文字はエラーになります。文字列の長さの上限とクラウド設定の条件は、USBで設定する場合と同じです。ファイルの検証に失敗した場合は、どの項目も適用せず、エラーを表示してオフラインの既定値で動作します。カード上の認証情報は暗号化されていないため、カードへの物理的なアクセスを制限してください。

## USBからNVSへ設定する

Wi-Fiとクラウドの設定や測定間隔などは、Core2の内蔵フラッシュにあるNVSへ保存します。NVSはアプリケーション領域とは別のパーティションにあるため、電源を切っても、通常の書き込み（Upload）でプログラムを更新しても、設定は残ります。フラッシュ全体やNVSを消去した場合、またはパーティション構成を変更した場合は、設定が消えることがあります。NVSへの保存は暗号化していないため、Core2への物理的なアクセスを制限してください。使用する前に、USBでの設定転送、NVSへの保存、Core2からmicroSDへのログ書き込みが社内ポリシーで許可されていることを確認してください。

1. ロガーのファームウェアをCore2に書き込み、PCとUSBで接続します。
2. VS Code／Arduinoのシリアルモニタを閉じます。
3. PCで次のコマンドを実行します。COM番号は実際のポートに合わせてください。

```powershell
py -m pip install pyserial
py .\scripts\configure_logger.py --port COM4
```

Wi-FiのSSIDとパスワード、GASのURLとトークン、その他の設定を対話形式で入力します。パスワード、URL、トークンは入力中に表示されません。既定値を使う項目では、そのままEnterキーを押します。入力した設定はPC上のファイルには保存せず、USB経由でCore2へ送ります。入力が終わると、ツールはCore2の応答を待ちます。このときCore2がスリープ中または応答しない場合は、Core2のリセットボタンを押してください。Core2は起動後の3秒間、センサとWi-Fiの処理を始める前にUSBからの設定を受け付けます。

`NVS configuration saved`と表示されたら、保存は成功です。Core2は自動で再起動し、NVSの設定で動作します。この方法はmicroSDがなくても使え、再ビルドも必要ありません。エラーや確認応答のタイムアウトは、保存成功の確認にはなりません。ポート、入力値、実機の状態を確認してください。

対話入力の代わりに、PCのローカルディスクに置いた非公開のJSONファイルを送ることもできます。

```powershell
py .\scripts\configure_logger.py --port COM4 --file .\slt5006-config.json
```

```json
{
  "wifi_ssid": "YOUR_WIFI_SSID",
  "wifi_password": "YOUR_WIFI_PASSWORD",
  "gas_url": "https://script.google.com/macros/s/REPLACE_WITH_DEPLOYMENT_ID/exec",
  "gas_token": "REPLACE_WITH_RANDOM_TOKEN",
  "sample_interval_sec": 60,
  "upload_batch_size": 10,
  "ntp_server": "pool.ntp.org",
  "timezone": "JST-9",
  "deep_sleep_sec": 0
}
```

設定ファイル、Wi-Fiのパスワード、GASのトークン、実際のデプロイURLはGitHubにコミットしないでください。`slt5006-config.json`は`.gitignore`で除外していますが、別名で保存したファイルは除外されません。Core2を紛失した場合や認証情報が漏れた場合は、認証情報を変更してください。

### USBプロトコル（115200 baud）

`CONFIG BEGIN`と改行を送り、`[CONFIG] READY`を受け取ってから、UTF-8のJSONオブジェクトを1行で送り、最後に改行を送ります。JSONは最大2048バイト（末尾の改行を除く）で、改行はLFとCRLFのどちらでも使えます。検証とNVSへの保存の両方に成功した場合だけ`[CONFIG] SAVED`を返し、再起動します。失敗した場合は`[CONFIG] ERROR ...`を返します。応答には設定値や認証情報を含めません。

`CONFIG CANCEL`を送ると中止できます。設定モードの間は、測定、送信、スリープへの移行を一時停止します。設定モードは120秒で終了します。行の途中で受信が途切れた場合、その行は10秒後に破棄します。検証に失敗した入力は保存しません。中止コマンドを受け取った場合も、新たな書き込みはしません。

保存の応答を受け取れなかった場合でも、設定は保存されていることがあります。再試行する前に実機を確認してください。測定中に設定モードに入ると、中止後にその測定がタイムアウトになることがあります。通常は、ツールが待機している間にCore2をリセットし、測定が始まる前に設定してください。

## 設定キー

| キー | 既定値／範囲 | 説明 |
|---|---|---|
| `wifi_ssid` | 空 | 接続先のSSID。空ならWi-Fiは無効 |
| `wifi_password` | 空 | Wi-Fiのパスワード |
| `gas_url` | 空 | HTTPSのGAS `/exec` URL。空なら送信は無効 |
| `gas_token` | 空 | GASの`INGEST_TOKEN`と同じ値 |
| `sample_interval_sec` | 60、5～86400 | 連続動作時の測定開始の間隔 [秒] |
| `upload_batch_size` | 10、1～20 | 1回のPOSTで送る最大行数 |
| `ntp_server` | `pool.ntp.org` | NTPサーバ名 |
| `timezone` | `JST-9` | ESP32のPOSIX形式のタイムゾーン文字列 |
| `deep_sleep_sec` | 0、または10～86400 | 0は連続動作。10以上は測定後にディープスリープする時間 [秒] |

`timezone`はIANA名ではなく、ESP32/POSIX形式で指定します。日本は`JST-9`です。ほかの地域で使う場合は、UTCオフセットの符号が一般的な表記と逆になることと、夏時間の規則に注意してください。ロガーが出力するJSON/CSVの`ts`は、地域にかかわらずUTCの`Z`形式です。GAS側の`TIME_ZONE`はシートの表示に使うIANA名（例:`Asia/Tokyo`）で、`timezone`とは形式が異なります。

USBで設定するたびに、設定全体が置き換わります。省略したキーは既定値に戻ります。`{}`を送ると、このロガーの設定をオフラインの既定値に戻せます（NVSのほかのデータは消去しません）。未知のキー、型の誤り、範囲外の整数はエラーになり、保存しません。数値の項目はJSONの整数で指定し、文字列、小数、真偽値は使わないでください。文字列中の空白は、パスワードも含めてそのまま保存します。文字列の上限（UTF-8のバイト数）は、SSID 32、パスワード 64、URL 512、トークン 256、NTPサーバ 253、タイムゾーン 128です。NUL文字と、空のNTPサーバ・タイムゾーンは使えません。クラウドを使う場合は、SSID、HTTPSのURL、トークンをすべて指定します。クラウドを無効にする場合は、URLとトークンを両方とも空にします。PCのツールは、重複したキーもエラーにします。

## microSDがない場合

センサの測定と画面表示には、microSDは必要ありません。カードがない場合や初期化に失敗した場合も、Core2はNVSに設定した周期で測定し、結果を画面とUSBシリアルに表示します。Wi-FiとNTPもNVSの設定どおりに動作します。ただし、次の機能は使えません。

- `/slt5006.csv`への記録
- `/slt5006_queue`への未送信行の保存と再送
- クラウドへの送信（SDのキューを経由して送信するため、直接は送信しません）

microSDがなく、NVSも未設定の場合は、オフラインの既定値（60秒周期）で測定します。

記録やクラウドへの送信を始める前に、画面に表示されたSDのエラーを解消してください。

## 操作

画面では、項目名、右寄せの数値、単位をそれぞれ固定の列にそろえて表示します。どの培地を選んでも、温度（`Temp`）、VWC、EC bulkの順に並びます。電池欄の下には、センサのシリアル番号とファームウェアバージョンを表示します。センサ情報を取得できていない場合は`unavailable`と表示します。

センサの測定に失敗すると、保持している直近の正常値に`(STALE)`を付けて表示します。この表示は送信に成功しても消えず、次に測定が成功したときに解除します。

測定周期（既定60秒）と画面の更新周期（0.5秒）は独立しています。画面はバッファ上に描画してからまとめて転送するため、更新のたびに画面が黒くなるちらつきを抑えられます。バッファを確保できなかった場合はエラーを表示し、画面へ直接描画して動作します。測定に`sample_interval_sec`より長い時間がかかった場合も、測定が終わってから次の測定を始めるまでに、送信と再接続を処理するループを1回挟みます。このため、長い測定やタイムアウトが続いても、次の測定の開始によって送信と再接続が妨げられることはありません。

`SLT5006 supply`は、センサが報告する供給電圧です。背景色を変えた`Core2 battery (est.)`欄には、Core2の電池残量の目安と電圧を表示します。この欄はセンサの測定が成功する前から表示し、メインループの動作中は5秒ごとに値を取得します。残量%は負荷や充電状態によって変動する目安です。値を取得できない場合は`unavailable`と表示し、シリアルモニタにも出力します。残量%は画面に表示するだけで、CSVやクラウドへの記録には含めません。

画面下部のタッチボタンで操作します。

| ボタン | 動作 |
|---|---|
| A | `Manual measurement`: 周期を待たずに測定を要求。測定中の場合は、その測定の完了を待つ |
| B | 表示する培地を`General` → `Rock wool` → `Coco`の順に切り替え |
| C | `Upload/reconnect`: Wi-Fiの再接続と、保存済みキューの送信を要求 |

ボタンBは、表示する換算値を切り替えるだけです。3種類のVWCは、同じ測定を培地ごとに換算した値です。一般土壌には`vwc_pct`、ロックウールには`vwc_rock_pct`、ココピートには`vwc_coco_pct`を使います。Pore ECについても、用途と、製品資料に記載された適用条件を確認してください。ロックウールを選ぶと、`EC pore`の行は表示しません。ココピートを選んだとき、センサのファームウェアが非対応または不明の場合は、Pore ECを`--`と表示します。一般土壌向けのPore ECで代用することはありません。

この切り替えは画面表示だけに反映され、CSVへの保存やクラウドへの送信の内容は変わりません。選択中の培地にかかわらず、3種類のVWC換算値とEC値を記録します。ココピート向けのPore ECは、センサのファームウェアが対応している場合だけ送信します。Core2の電池残量%は送信しませんが、電池電圧は記録します。送信先は、使用中のNVSまたはSDの設定にある`gas_url`（HTTPSの`/exec` URL）です。`gas_token`は、GASの`INGEST_TOKEN`と同じ値にします。USBでの保存に成功すると、Core2は自動で再起動します。SDの設定を編集した場合は、手動で再起動してください。設定の変更に再ビルドは必要ありません。

センサの変換完了は、ほかの処理を止めないポーリングで待ちます。そのため、待っている間も画面とネットワークの処理を続けられます。ただし、1回のUARTの送受信、microSDへの書き込み、HTTPS通信の間は、ほかの処理が短時間止まることがあります。

## 保存ファイルと再送

成功した測定とセンサ通信のエラーは、`/slt5006.csv`に追記します。エラーの行は測定値が空欄になり、`error`列に理由が入ります。列名には単位を含めています。代表的な列は次のとおりです。

```text
id,ts,serialNumber,firmware,battery_v,core2_battery_v,temperature_c,vwc_pct,vwc_coco_pct,vwc_rock_pct,ec_bulk_dsm,ec_pore_dsm,ec_pore_coco_dsm,rssi_dbm,error
```

CSVをコピーするときは、Core2を停止し、カードを安全に取り外してから行ってください。Excelなどで開いたCSVをカードに書き戻さないでください。

`battery_v`はセンサが報告するセンサの電源電圧、`core2_battery_v`はCore2の内蔵電池の電圧です。Core2の電池電圧を取得できない場合は、JSONではnull、CSVでは空欄にします。0や負の値を記録することはありません。センサのファームウェアがココピート向けPore ECに対応していない場合も、その値は0ではなく空欄にします。RSSIの`-127`は、Wi-Fiに接続していないことを示します。

CSVへの書き込みでは、ヘッダと各行のすべてのバイトが書き込まれたことを確認します。一部しか書き込めなかった場合は、失敗として表示します。その場合も、キューへの保存に成功した行はクラウドへの送信用に残ります。SDへの書き込みでエラーが出たときは、CSVに不完全な行が残っていることがあります。Core2を停止し、CSVを確認してバックアップしてから運用を再開してください。

クラウドへの送信を待つ各行は、再送しても変わらない`id`を付けて`/slt5006_queue`に保存します。送信の前にキュー全体を走査し、JSONに記録したUTCの測定日時`ts`が古い行から選びます。時刻が同期していないために`ts`が空の行は、日時のある行より先に送ります。日時が同じ行（空の場合を含む）は、ファイル名の順に選びます。メモリに保持するのは1回に送る行（既定10行、最大20行）だけなので、メモリ使用量はキューの全件数に比例しません。ただし、走査にかかる時間は件数に応じて増えます。キューに行が追加されなければ、成功したバッチを削除するたびに、古い順に送信が進みます。この送信順の処理は、CSVの並びと保存形式、および成功応答を確認してからキューを削除する条件には影響しません。

キューの各JSONファイルは最大2048バイトです。既存のIDのファイルは上書きしません。サイズが上限を超えるファイル、最後まで読み出せないファイル、NUL文字を含むファイル、不正なJSON（末尾に余分なデータがあるものを含む）のファイルは、削除せずに送信バッチから除外し、USBシリアルにファイル名を表示します。キューを開けない場合や、不正なファイルしか残っていない場合は、キューが空で成功したとは扱わず、エラーを表示します。

送信が成功したと判断するのは、HTTPSの2xx応答に加えて、GASが返すJSONの`ok:true`を確認したときだけです。失敗、タイムアウト、応答が不明な場合はファイルを残し、次回の送信時またはボタンCを押したときに、同じIDのまま再送します。GAS側でも保存済みのIDを検出するため、応答だけが失われた場合でも、同じ行が二重に記録されるのを防げます。

GASの結果取得先への302／303リダイレクトは、新しい接続を使ってGETで取得します。USBシリアルに出力される`[UPLOAD] hop=... method=... status=...`で、最初のPOSTと結果取得のGETのどちらで失敗したかを確認できます。HTTPS以外のリダイレクト先には接続しません。各要求では接続を再利用せず、HTTPの終了処理の前にTLS接続を明示的に閉じます。これにより、リダイレクトの本文を破棄するときに、不要な受信確認をしないようにしています。この処理によって、POST、GET、応答本文の読み取り中に起きたエラーが隠れることはありません。

ブロッキング処理の前には画面を再描画し、`Connecting Wi-Fi...`、`Preparing upload...`、`Uploading ... row(s)...`、`Fetching upload result...`を、`Measuring...`とは区別して表示します。HTTPS送信は同期処理のため、送信中はボタン操作を受け付けません。`[UPLOAD] accepted_rows=... queue_cleaned=1`は、成功応答の確認と、SDのキューからの該当バッチの削除が両方とも完了したことを示します。

過去にセンサ通信に失敗した記録も、キューから送信します。`serialNumber=0`で、ファームウェアと測定値が空欄、`error`に`sensor response timed out`がある行は、センサ情報を取得できなかったときの試行を記録したエラー行です。現在の正常な測定とは、`id`と日時で区別してください。

キューは運用中のデータです。手動で削除したり、IDを変更したりしないでください。microSDの故障や容量不足に備えて、CSVを定期的に別の媒体へバックアップし、カード上のキューのファイル数と空き容量を監視してください。

## ディープスリープ

`deep_sleep_sec=0`では通常の連続動作になります。10以上を指定すると省電力モードになり、起床するとすぐに1回の測定を試み、SDへの保存と送信を試みた後、指定した秒数だけスリープします。センサの測定に失敗した場合も、その試行の後にスリープします。スリープ中は、画面表示、Wi-Fi、ボタン操作、測定のいずれも動作しません。このモードでは`sample_interval_sec`を使いません。起床のたびに再起動、センサの安定待ち、Wi-Fi/NTPの接続が加わるため、測定開始から次の測定開始までの実際の間隔は、スリープの秒数より長くなります。

電池で運用する前に、実機で次の項目を評価してください。

- スリープ中のCore2、Bottom、センサの電源の状態
- UARTを通じた逆給電が起きないこと
- NTPに失敗したときの時刻、Wi-Fiの接続時間、消費電流
- SDへの書き込みが完了してからスリープに入ること、電源断からのファイルの回復
- `sample_interval_sec`による連続動作との使い分けと、測定開始から次の測定開始までの実際の周期

## 動作確認の手順

1. `M5Core2QuickStart`で、ファームウェアバージョン、シリアル番号、温度、VWC、ECが表示されることを確認します。
2. NVSにもSDにも設定がない状態で起動し、オフラインで動作することと、USB設定の案内を確認します。
3. USBから設定し、USBシリアルまたはCSVでUTCの`ts`を確認します。`/slt5006.csv`に1行記録されることも確認します。
4. Wi-Fiを一時的に切り、測定結果がCSVとキューに残ることを確認します。
5. Wi-Fiを戻してボタンCを押し、GASに1回だけ追記され、キューが減ることを確認します。
6. 電源を切った状態でセンサを外し、タイムアウトが表示されることを確認します。その後、電源を切った状態でセンサを接続し直し、復旧することを確認します。
7. 実際の設置場所で、RSSI、連続運転、電源、SDの容量、乾湿の変化に対する応答を評価します。
8. 電源を切った後や、通常の書き込み（Upload）でファームウェアを更新した後も、設定が残ることを確認します。また、SDなしでの設定、不正な入力と中止、ディープスリープ中にリセットしてからの設定を確認します。
9. NVSが未設定のときにSDの設定が適用されること、NVSに保存した後はSDの設定より優先されることを確認します。
10. ココピートのPore ECが非対応または不明のときに`--`と表示されること、センサの測定に失敗した後に`(STALE)`が付くこと、SDでエラーが起きても送信待ちの行が残ることを確認します。
11. 測定間隔を5秒にし、応答の遅いセンサを模擬する試験用治具を使って、長い測定やタイムアウトの合間にも送信と再接続が実行されることを確認します。

## よくある問題

| 状態 | 最初に確認すること |
|---|---|
| センサのタイムアウト | [配線](m5stack-wiring.ja.md)、選択したGPIO（PORT.A 32/33またはPORT.C 13/14）、電源、Enable、TX/RX、9600 8N1 |
| SDのエラー | カードの装着、対応フォーマット、接点、空き容量、電源を切った状態での再装着 |
| Wi-Fiがオフライン | SSIDとパスワード、2.4 GHz帯のアクセスポイント、電波状態、使用中のNVS／SDの設定 |
| 時刻が正しくない | インターネット接続とNTP、`ntp_server`、USBシリアル／CSVの`ts`と`time_not_synchronized` |
| キューが減らない | `gas_url`、トークン、GASのデプロイ、JSONの`ok`、実行ログ |
| Upload transport -1 | Wi-Fi接続後のDNS／TCP／TLS接続の失敗。USBシリアルの`[UPLOAD]`診断を確認 |
| ココピートのPore ECが空欄 | ファームウェアが1.7.5未満、またはファームウェア情報を取得できていない（仕様どおりの省略） |

クラウド側の設定は[GASセットアップ](gas-setup.ja.md)を、自社システムへの組み込みは[組み込みガイド](m5stack-integration.ja.md)を参照してください。

Wi-Fiの`online`は、アクセスポイントに接続していることを示すだけで、GASに到達できるかどうかは示しません。送信結果の負の値は、サーバが返したHTTPステータスではなく、ESP32の通信ライブラリのエラーです。原因を調べるには、115200 baudでシリアルモニタを開き、ボタンCを押して再送を要求します。`[UPLOAD]`行には、通信エラーの説明、TLSのエラーコードと説明、Wi-Fiの状態、RSSI、時刻の有効性を出力します。URL、トークン、送信内容は出力しません。

`clock_valid=0`の場合は、時刻同期を確認してください。TLSのエラーが出ている場合は、証明書の検証、時刻、通信経路を確認してください。TLSのエラーコードが0でも、DNSやTCPの接続などで失敗していることがあります。証明書の検証は無効にせず、診断情報から原因を特定してください。送信に失敗したデータはSDのキューに残ります。

Googleとの通信に使う信頼済みのルート証明書として、GTS Root R1／R4を組み込んでいます。TLSの`-9984`は、証明書の検証に失敗したことを示します。信頼済みのルート証明書が足りない場合のほか、時刻がずれている場合や、通信経路上で証明書が置き換えられている場合にも発生します。`clock_valid=1`は年が2024年以降であることしか確認しないため、USBで出力される測定JSONのUTC `ts`も実際の時刻と比べてください。
