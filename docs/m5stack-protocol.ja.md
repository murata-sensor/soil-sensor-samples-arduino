# SLT5006 UARTプロトコル

[English](m5stack-protocol.md) | 日本語

この資料では、本リポジトリのドライバがセンサ情報と測定値の取得に使う通信だけを説明します。レジスタマップ全体、電気定格、保証条件は、SLT5006の最新の製品資料を参照してください。顧客向けに公開されているレジスタ以外にはアクセスしないでください。

この資料の通信内容と換算は、`soil-sensor-samples-arduino`および`soil-sensor-samples-python`のSLT5006実装と互換です。

## UART設定

| 項目 | 値 |
|---|---|
| ボーレート | 9600 bps |
| データビット | 8 |
| パリティ | なし |
| ストップビット | 1 |
| フロー制御 | なし |
| 接続台数 | 1台 |

SLT5006には機器アドレス（スレーブID）がありません。フレームの先頭バイトは機能コードです。

## フレーム

読出し要求は5バイトです。

```text
01  ADDRESS  SIZE  CRC_H  CRC_L
```

1バイトの書込み要求は6バイトです。

```text
02  ADDRESS  01  DATA  CRC_H  CRC_L
```

正常応答は次の形式です。書込みの応答では、要求したアドレス、サイズ、データがそのまま返ります（エコー）。

```text
FUNCTION  ADDRESS  SIZE  DATA[SIZE]  CRC_H  CRC_L
```

エラー応答は4バイトです。

```text
(REQUEST_FUNCTION | 0x80)  ERROR_CODE  CRC_H  CRC_L
```

`SIZE`は1～26バイトで、正常応答は最大31バイトです。改行、終端文字、STX/ETXは付きません。受信側は、先頭バイトのビット7で4バイトのエラー応答かどうかを判定します。エラー応答でなければ、3バイトのヘッダーにある`SIZE`から残りの長さを求めます。

### 動作確認用の要求フレーム

| 操作 | 要求フレーム（16進） |
|---|---|
| ファームウェア読出し | `01 00 03 01 60` |
| シリアル番号読出し | `01 03 04 33 21` |
| 測定開始 | `02 07 01 01 0D 70` |
| 状態読出し | `01 08 01 00 E6` |
| 測定値読出し | `01 11 12 5D AC` |

## CRC

CRCの計算方法は、CRC-16/MODBUSと同じです。

- 初期値: `0xFFFF`
- 反転多項式: `0xA001`
- 各データバイトをXORした後、LSBファーストで8回シフト

ただし、SLT5006は計算結果を**上位バイト、下位バイト**の順に送信します。下位バイトから送る一般的なMODBUS RTUとは、順序が逆です。

擬似コード:

```text
crc = 0xFFFF
for byte in payload:
    crc ^= byte
    repeat 8 times:
        crc = (crc >> 1) ^ 0xA001  if (crc & 1) else (crc >> 1)
send (crc >> 8), (crc & 0xFF)
```

## センサ情報

| 開始アドレス | サイズ | 内容 |
|---|---:|---|
| `0x00` | 3 | ファームウェアのメジャー、マイナー、リビジョン（各uint8） |
| `0x03` | 4 | シリアル番号（リトルエンディアンのuint32） |

Cloud Loggerは、`firmware`を`major.minor.revision`の形式で保存します。`serialNumber`は、CSVには10進数、JSONには数値として保存します。付属のGASが、これをスプレッドシート用の文字列に正規化します。

## 測定シーケンス

1. `0x07`に`0x01`を1バイト書き込み、ACKのCRC、機能コード、アドレス、サイズ、データが正しいことを確認します。
2. ACKを受信してから最初の状態読出しまで、300 ms以上待ちます。
3. `0x08`を1バイト読み、ビット0が1になるまで200 ms以上の間隔で読出しを繰り返します。
4. 開始ACKからの経過時間が既定値の30秒に達したら、新しい状態読出しは始めずに測定タイムアウトとします。その時点でUART応答待ちが実行中なら、全体の所要時間はその分だけ30秒より長くなります。
5. 測定完了後、`0x11`から18バイトを読み出し、値を換算します。

測定開始のACKは、要求を受け付けたことを示すだけです。測定が完了したかどうかは、手順3で確認します。

## 測定データ

複数バイトの値は、リトルエンディアン（下位バイトが先）です。`0x11`から読み出す18バイト（9ワード）のうち、ドライバが公開する値は次のとおりです。

| ワード | C++メンバー | JSON / CSV | 換算・単位 |
|---:|---|---|---|
| 1 | `batteryVoltageV` | `battery_v` | `raw * 3.3 / 4096 / 0.5` V |
| 2 | `temperatureC` | `temperature_c` | 符号付き下位12ビット × 0.0625 degC |
| 3 | `ecBulkDsM` | `ec_bulk_dsm` | uint16 × 0.001 dS/m |
| 4 | `vwcRockPercent` | `vwc_rock_pct` | uint16 × 0.1 % |
| 5 | `vwcPercent` | `vwc_pct` | uint16 × 0.1 % |
| 6 | `vwcCocoPercent` | `vwc_coco_pct` | uint16 × 0.1 % |
| 8 | `ecPoreDsM` | `ec_pore_dsm` | uint16 × 0.001 dS/m |
| 9 | `ecPoreCocoDsM` | `ec_pore_coco_dsm` | uint16 × 0.001 dS/m |

`batteryVoltageV` / `battery_v`は、SLT5006が報告する**センサ側の電源電圧を換算した値**です。Core2内蔵電池の電圧はロガー独自の`core2_battery_v`で、これとは別の値です。

温度は、下位12ビットを2の補数として符号拡張してから0.0625を掛けます。16ビット全体を符号付き整数として扱わないでください。表にないワードは公開しません。

### ファームウェアによる機能の違い

ココピート向けPore ECは、SLT5006のファームウェア1.7.5以降で使用できます。

- 1.6.3: `ecPoreCocoDsM`は非対応
- 1.7.5、1.7.6: 対応

それより古いファームウェアでも18バイト全体とワード9を読み出せますが、ワード9の値は0で、有効な測定値ではありません。ファームウェアが非対応または不明の場合は、この値を画面に表示しません。列構成が固定のCSVでは該当列を空欄にし、JSONではプロパティを省略します。

## センサエラー

| コード | 意味 |
|---:|---|
| `0x01` | 不正な機能コード |
| `0x02` | 不正な開始アドレス |
| `0x03` | 不正なバイト数 |
| `0x04` | 内部受信バッファのオーバーフロー |
| `0x05` | CRC-16エラー |
| `0x06` | 測定中のデータ読出し |
| `0x10` | 内部記憶領域への書込み失敗 |
| `0x20` | センサ内部の通信エラー |
| `0x40` | センサ側の測定タイムアウト |

エラー応答も、CRCと`REQUEST_FUNCTION | 0x80`を検証してから採用します。未知のコードは破棄せず、16進数のコード値を含めてエラーとして記録してください。

## 実装で必ず検証する項目

- 要求の全バイトを書き込めたこと
- 必要なバイト数の応答が、タイムアウト時間内に届いたこと（応答が分割して届く場合を含む）
- 正常応答の`SIZE`が1～26で、固定長のバッファに収まること
- CRCの値と、上位バイトから送る順序が正しいこと
- 正常応答の機能コード、アドレス、サイズが正しいこと
- 書込みACKのアドレス、サイズ、データが要求のエコーになっていること
- エラー応答の機能コードとCRCが正しいこと
- 符号付き12ビットの温度、リトルエンディアンの値、換算係数を正しく扱うこと
- 最初の状態読出しまでの300 ms、以後のポーリング間隔、測定全体のタイムアウトを守ること
- `millis()`が最大値から0に戻っても、経過時間を正しく計算できること

通信エラーの後は、同じ要求を続けて送り直さないでください。残っている受信データを破棄してフレームを再同期し、間隔を置いて、新しい測定の開始から再試行してください。組み込み方針は[システム組み込みガイド](m5stack-integration.ja.md)を参照してください。
