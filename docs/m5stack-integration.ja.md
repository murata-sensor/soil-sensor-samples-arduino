# システム組み込みガイド

[English](m5stack-integration.md) | 日本語

最初の動作確認には`M5Core2QuickStart`を、ロガーの評価には`M5Core2CloudLogger`を使います。量産品や自社システムに組み込むときは、UI、保存、通信、認証の処理を分け、次の境界をはっきりさせてください。

```text
SLT5006 UART driver -> Measurement -> display / local CSV / upload queue -> GAS
```

## Arduino版との互換性

M5Core2版のSLT5006ドライバは、Arduino版と同じ`Stream`ベースのAPIとデータ型を使います。M5Core2ではUART2を初期化してドライバに渡します。次の例は本体のPORT.A（`RX=32, TX=33`）を使います。対応するBottomのPORT.Cを使う場合は、`RX=13, TX=14`に変更してください。

```cpp
HardwareSerial sensorSerial(2);
SLT5006 sensor(sensorSerial);

void setup() {
  sensorSerial.begin(SLT5006::BAUD_RATE, SERIAL_8N1, 32, 33);
}
```

単純な処理には`readMeasurement()`を使います。画面表示やネットワーク処理を続けながら測定変換を待つ場合は、次の協調APIを使います。

```text
IDLE --startMeasurement()--> MEASURING
MEASURING --measurementComplete(false)--> MEASURING
MEASURING --measurementComplete(true)--> READY
READY --readMeasurementData()--> IDLE
```

協調APIで分割できるのは測定変換の待ち時間だけです。UARTの応答を待つ間は呼出し元が止まり、その時間は最長で応答タイムアウト1回分です。同じ`Serial2`を複数のタスク、割込み処理、別のライブラリから同時に操作しないでください。UARTの操作は1つのタスクにまとめてください。詳しいタイミングとフレームは[プロトコル資料](m5stack-protocol.ja.md)を参照してください。

## 保存・送信時の項目名と単位

| C++ | 保存／JSON | 単位 |
|---|---|---|
| `batteryVoltageV` | `battery_v` | センサが報告する電源電圧 [V] |
| Core2の電源API | `core2_battery_v` | Core2の内蔵バッテリー電圧 [V] |
| `temperatureC` | `temperature_c` | degC |
| `vwcPercent` | `vwc_pct` | %（一般土壌） |
| `vwcRockPercent` | `vwc_rock_pct` | %（ロックウール） |
| `vwcCocoPercent` | `vwc_coco_pct` | %（ココピート） |
| `ecBulkDsM` | `ec_bulk_dsm` | dS/m |
| `ecPoreDsM` | `ec_pore_dsm` | dS/m |
| `ecPoreCocoDsM` | `ec_pore_coco_dsm` | dS/m（対応ファームウェアのみ） |

列名やAPI名に単位を含め、暗黙の単位変換を避けます。通信の成否と測定値の妥当性は、分けて判断してください。用途に合う培地のVWCを1つ選び、設置方法、仕様範囲、飽和、異常値の扱いをシステム要件として定義してください。ドライバは受信した値を仕様範囲内に収める処理をしません。

起動時にファームウェアのバージョンとシリアル番号を読みます。ファームウェア1.7.5未満でもword 9は読み出せますが、その値は0で、測定値としては使えません。`ec_pore_coco_dsm`はファームウェア1.7.5以降の場合だけ保存・表示し、それより前のファームウェアや、ファームウェアを識別できなかった場合は欠損値にします。

## タイムアウトと再試行

既定値は、UARTの応答タイムアウトが300 ms、状態確認のポーリング間隔が200 ms、測定全体の期限が30秒です。開始ACKから最初の状態確認までは、最低300 ms待ちます。これらの値を短くすると正常な遅れを故障と誤判定することがあり、長くすると断線の検出が遅れます。変更した場合は、実際のセンサ、配線、温度、処理負荷で評価してください。

推奨するエラー処理:

1. エラーの種類、センサのエラーコード、時刻、連続失敗回数を記録する。
2. 同じ要求を繰り返し送らず、受信を再同期してから次の測定周期で再試行する。
3. CRCエラーや応答形式のエラーが出たら、電源、GND、ロジックレベル、ノイズ、配線長を確認する。
4. 失敗が続くときの再試行には指数バックオフと上限を設け、ウォッチドッグによるリセットの繰り返しを防ぐ。
5. 配線を変更するときは、必ずすべての電源を切る。

`millis()`で経過時間を求めるときは符号なしの減算を使い、`millis()`が最大値から0に戻っても正しく動くようにします。処理に厳密な期限がある場合は、変換待ちの期限に加えて、測定開始、状態確認、最終読出しのそれぞれのUART応答タイムアウトも上位の設計に含めてください。

## 送信前にローカルへ保存する

クラウドへの送信に失敗しても測定値を失わないように、1回の測定結果を次の順で処理します。

1. 項目名付きのレコードを作り、再送しても変わらない一意の`id`を付ける。
2. 最大2048バイトのレコードを一時ファイルに全バイト書き込み、フラッシュしてファイルを閉じてから、ファイル名を変更してキューに入れる。同じIDのレコードがすでにある場合は上書きしない。
3. 同じレコードをCSVに追記し、ヘッダと行の書込みバイト数を確認してから、フラッシュしてファイルを閉じる。
4. HTTPSで送信し、最終的な応答がHTTP 2xxであることと、JSONが`ok:true`であることの両方を確認する。
5. 送信の成功を確認できた場合だけ、キューのレコードを削除する。

キューとCSVへの書込みは、それぞれ成否を確認します。クラウドへの配送を守るため、キューへの保存を優先します。一時ファイルに書いてから名前を変更する方法でも、カードによっては電源断で書込み内容が失われたり壊れたりすることがあります。CSVへの記録中やキューの作成中に電源が切れる場合も考慮し、起動時に不完全なファイルを検出して隔離してください。容量の上限、保持期間、バックアップ、カードの摩耗、時刻が未同期の場合の扱い、CSVインジェクションを含む外部入力のエスケープも設計してください。

CSVとクラウドで同じ測定を対応付けるキーは`id`です。`serialNumber + ts`だけでは、時計の補正や同じ秒に行った手動測定でキーが重複するため、端末側で永続化したカウンタなども組み合わせてください。

## 時刻

JSONの`ts`は、UTCオフセットまたは`Z`を付けたISO 8601形式にします。NTPで同期する前の時刻を、正しい日時として記録しないでください。サンプルロガーは、時刻が未同期のときは`ts`を空にし、`error=time_not_synchronized`と安定した`id`を保存します。付属のGASはこの場合に限り、サーバーでの受信時刻をスプレッドシートのDateに使います。この値は測定時刻ではありません。

正確な時系列が必要な製品では、RTCによる時刻保持、同期品質を示すフラグ、起動時刻と単調増加のオフセット、再同期による時刻の飛びへの対処方針を追加してください。

## ネットワークと認証

- URLは`https://`だけを許可し、TLS証明書とホスト名を検証する。
- GASのリダイレクトは、最終的な応答まで安全にたどる。
- HTTPステータスだけでなく、JSONのスキーマと`ok:true`も検証する。
- Wi-Fiのパスワードとトークンを、ソースコード、USB経由のログ、画面、クラッシュダンプに出さない。
- タイムアウト、回数に上限のある再試行、バックオフ、キューの上限を設ける。
- トークンが漏えいしたときに交換できる手順を用意する。

共有トークンは、評価や小規模な用途向けです。多数の端末で運用する場合は、端末ごとの認証情報、失効、レート制限、監査ログを備えた受信APIを検討してください。

## 省電力と電源

スリープやセンサの電源制御には、ソフトウェアだけでなく回路の検討も必要です。Core2がスリープしてセンサが動作し続ける場合や、その逆の場合に、UARTを通じて逆給電しない回路が必要です。EnableをGPIOで制御するように変更する場合は、端子の定格、起動時のピンの状態、駆動回路、電源が安定するまでの待ち時間、異常時に電源を切る順序を評価してください。SDカードへの書込み中やHTTPS送信中は、スリープや電源オフをしないでください。

## 移植時の検証項目

- [配線](m5stack-wiring.ja.md): GPIO、信号の向き、電源、片側だけの電源断
- UART: 既知のフレーム、分割された応答、残留バイト、タイムアウト、CRCエラー
- プロトコル: エラーフレーム、エコーの不一致、最大サイズ、符号付きの温度値、ファームウェアのバージョン境界
- 測定スケジュール: 手動測定と周期測定の競合、`millis()`のオーバーフロー、Wi-Fiの遅延中の測定
- 保存: 初回のヘッダ、CSVのクォート、カードの満杯、抜去、破損、書込み途中のリセット
- アップロード: オフラインからの復帰、リダイレクト、TLSの失敗、401相当のエラー、GASの`ok:false`、重複した再送
- 時刻: NTPなし、タイムゾーン、再同期、ディープスリープからの復帰
- 耐久性: 実際の設置環境での連続運転、RSSI、温度、電源の余裕、乾湿の変化

実機での試験でも、活線挿抜はしないでください。故障を模擬する場合は、試験用に用意したスイッチや治具を使ってください。
